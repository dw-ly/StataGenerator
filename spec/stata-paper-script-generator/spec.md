# Stata 论文脚本生成器需求规格说明

> 状态：草稿
> 创建日期：2026-03-17
> 所属里程碑：无

## 1. 概述

### 1.1 功能简介
提供一个界面，让用户通过选择论文实证分析相关维度并补充必要变量信息，自动生成可用于 Stata 的分析脚本。首版支持描述统计、基准回归、面板回归、双重差分和工具变量回归五类方法，同时提供网页版和 Windows EXE 桌面版。

### 1.2 所属模块
论文研究辅助工具 / Stata 脚本生成模块

### 1.3 关联文档
- 当前对话需求记录
- 无其他已知 PRD、roadmap 或既有 spec

## 2. 用户故事与场景

### 2.1 目标用户
- 需要编写实证分析代码的论文作者
- 需要快速搭建 Stata 分析脚本的研究生、教师或研究助理

### 2.2 用户故事
- 作为论文作者，我希望在界面上选择研究设计和变量配置，以便快速获得一份可编辑的 Stata 脚本初稿。
- 作为研究助理，我希望通过结构化表单输入研究参数，以便减少手写 Stata 命令时的重复劳动和格式错误。
- 作为进阶用户，我希望管理不同 Stata 版本模板，以便按自己的写作和运行环境切换脚本生成基线。

### 2.3 使用场景

场景一：用户要完成一篇面板数据论文的基准回归  
前置条件：用户已经明确因变量、自变量、控制变量、面板主键和时间变量。  
期望结果：系统生成包含数据读取、变量配置、基准回归和结果输出说明的 Stata 脚本。

场景二：用户要设计双重差分或工具变量模型  
前置条件：用户已经明确研究设计类型，并准备好处理变量、分组变量或工具变量。  
期望结果：系统根据所选研究方法生成对应的 Stata 脚本骨架，并提示缺失的关键输入。

场景三：用户要快速比较不同回归设置  
前置条件：用户能够在界面中切换标准误、固定效应、稳健性检验和输出内容。  
期望结果：系统根据新的选择重新生成脚本，供用户比较不同模型方案。

场景四：用户希望通过导入 ini 配置快速恢复研究设定  
前置条件：用户已经准备好一份本地 ini 配置文件。  
期望结果：系统读取 ini 配置并填充表单，减少重复录入。

场景五：用户希望管理 Stata 版本模板  
前置条件：系统已提供预置模板或用户已经保存过自定义模板。  
期望结果：用户能够选择模板，并对自定义模板进行保存或删除。

## 3. 功能需求

### 3.1 输入

系统应允许用户通过界面输入或选择以下信息：

- 研究类型，首版包括描述统计、基准回归、面板回归、双重差分、工具变量回归
- 数据结构，例如截面数据、面板数据、时间序列数据
- 因变量
- 核心自变量
- 控制变量列表
- 固定效应设置，例如个体、年份、行业、地区
- 标准误设置，例如普通标准误、稳健标准误、聚类标准误
- 稳健性检验需求，例如替换变量、缩尾、滞后变量、子样本回归
- 异质性分析需求，例如按行业、地区、规模分组
- 输出需求，例如描述统计表、相关系数表、回归结果表、图形
- 数据文件名或数据文件路径
- 面板主键变量和时间变量（当数据结构为面板数据时）
- 分组变量、处理变量、工具变量（当研究方法需要时）
- Stata 版本模板选择

系统应支持导入本地 ini 配置文件，并在成功解析后恢复研究方法、变量配置、输出选项、模板选择和其他可映射表单字段。

系统应支持用户输入自由文本补充说明，用于表达无法通过枚举选项完整覆盖的研究要求。

### 3.2 输出

系统应输出以下内容：

- 一份可复制或下载的 Stata 脚本文本
- 一份脚本说明，说明脚本覆盖的分析步骤和依赖输入
- 一份缺失项提示，指出当前生成结果仍依赖哪些未填写信息

当用户输入不足以支持所选研究方法时，系统应明确指出不能完整生成脚本的原因，并提示需要补充的字段，而不是生成含义不清的结果。

### 3.3 核心行为描述

- 系统在用户进入页面后展示与论文实证分析相关的结构化配置界面。
- 系统根据用户所选研究类型动态展示对应字段，避免无关字段同时出现。
- 系统在用户切换数据结构或研究类型后，自动调整所需输入项。
- 系统在用户完成必要字段输入后，基于所选维度组织一份 Stata 脚本初稿。
- 系统生成的脚本应体现常见论文分析流程，包括但不限于数据读取、基础处理、模型设定和结果输出占位。
- 系统应允许用户多次调整配置并重新生成脚本。
- 系统应在用户重新打开页面或应用时恢复最近一次配置，便于继续编辑。
- 系统应支持导入 ini 配置并将其映射到当前表单。
- 系统应提供 Stata 版本模板管理能力，使用户可以按版本选择模板。
- 系统应允许用户保存自定义版本模板，也允许用户删除自己保存的版本模板。
- 系统不区分新手模式和高级模式，但应将高级功能集中展示在单独区域。
- 系统应在生成结果中保留清晰注释，帮助用户理解各部分用途。
- 系统不得伪造不存在的变量名或研究设定；当用户未填写关键项时，应以提示替代推断。

### 3.4 业务规则与约束

- 该功能面向论文研究场景，不面向通用软件开发场景。
- 系统生成的是 Stata 脚本初稿，用户仍需根据真实数据和论文设计进行修改。
- 首版支持的方法范围限定为描述统计、基准回归、面板回归、双重差分和工具变量回归。
- 不同研究方法依赖的必要字段不同，系统必须按方法检查字段完整性。
- 当研究类型为面板回归时，面板主键变量和时间变量应被视为必填。
- 当研究类型为双重差分时，处理变量、时间划分或等价信息应被视为必填。
- 当研究类型为工具变量回归时，工具变量信息应被视为必填。
- 当用户选择聚类标准误时，聚类维度应被视为必填。
- 系统应优先使用用户显式输入的信息，不应自行推测研究设计细节。
- ini 配置导入用于恢复配置，不等同于自动完成研究设计。
- Stata 版本模板管理应区分系统预置模板与用户自定义模板。
- 用户仅可删除自己保存的模板，系统预置模板不可删除。

## 4. 非功能需求

### 4.1 性能要求
- 表单操作和配置切换应即时响应
- 在常规输入规模下，脚本生成应在可接受的交互等待时间内完成

### 4.2 安全要求
- 系统不得在未明确授权的情况下读取用户导入的本地配置文件
- 系统不得泄露用户输入的研究变量和论文设定
- 如涉及文件导入或保存，应限制可执行风险并明确文件用途

### 4.3 兼容性要求
- 界面应至少兼容桌面端使用
- 如提供浏览器界面，应支持主流现代浏览器
- 桌面版首版仅要求支持 Windows EXE 交付
- 输出的脚本文本应可直接用于常见版本的 Stata，或在说明中标明版本依赖

## 5. 边界与限制

### 5.1 明确包含（In Scope）
- 提供论文实证分析配置界面
- 根据配置生成 Stata 脚本骨架
- 根据研究方法显示不同输入项
- 对关键缺失项进行校验和提示
- 允许用户重复编辑并重新生成脚本
- 支持导入本地 ini 配置文件
- 保存并恢复用户最近一次配置
- 提供 Stata 版本模板管理
- 允许用户保存和删除自定义模板
- 将高级功能集中展示在单独区域
- 生成结果中附带必要说明和注释

### 5.2 明确排除（Out of Scope）
- 自动执行生成的 Stata 脚本
- 直接替用户完成论文方法选择
- 生成所有学科和所有计量方法的完整专家级脚本
- 自动撰写论文正文、结论或文献综述
- 通过新手/高手双模式切换界面

### 5.3 已知约束
- 首版产品形态明确为 Web 页面和 Windows EXE 桌面应用
- 首版方法范围已收敛，不覆盖 RDD、PSM、生存分析等扩展方法
- 首版导入能力收敛为 ini 配置导入
- 不区分新手和高手模式，但高级功能单独集中展示

## 6. 验收标准（Acceptance Criteria）

- **Given** 用户进入脚本生成页面  
  **When** 页面完成初始化  
  **Then** 用户可以看到研究类型、数据结构和变量配置等基础维度

- **Given** 用户选择某一研究类型  
  **When** 该研究类型有额外必填项  
  **Then** 页面展示与该方法对应的专用输入项

- **Given** 用户选择面板数据回归  
  **When** 未填写面板主键变量或时间变量  
  **Then** 系统提示缺失项，且不生成误导性的完整脚本

- **Given** 用户已填写生成某类模型所需的关键字段  
  **When** 用户点击生成  
  **Then** 系统输出一份结构化的 Stata 脚本初稿

- **Given** 用户修改了固定效应、标准误或稳健性检验配置  
  **When** 用户重新生成脚本  
  **Then** 输出结果反映新的模型配置

- **Given** 用户输入无法满足所选研究类型的要求  
  **When** 用户尝试生成脚本  
  **Then** 系统明确列出必须补充的信息，而不是自行猜测

- **Given** 用户成功生成脚本  
  **When** 用户查看结果  
  **Then** 用户可以区分脚本正文、说明信息和待补充项提示

- **Given** 用户选择导入本地 ini 配置文件  
  **When** 文件可被系统成功解析  
  **Then** 系统将配置映射到当前表单并允许用户继续修改

- **Given** 用户此前已经填写过配置  
  **When** 用户重新打开页面或桌面应用  
  **Then** 系统自动恢复最近一次配置，且用户可以继续修改并重新生成脚本

- **Given** 用户进入模板管理相关界面  
  **When** 用户选择某个 Stata 版本模板  
  **Then** 系统使用对应模板参与脚本生成

- **Given** 用户保存了自定义模板  
  **When** 用户在后续继续使用系统  
  **Then** 系统可以展示该模板并允许用户删除

- **Given** 用户查看页面中的高级功能  
  **When** 页面完成渲染  
  **Then** 高级功能被集中放置在单独区域，而不是通过新手/高手模式切换
