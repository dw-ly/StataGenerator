## 审查总结

当前工程骨架可构建，Web 与 Electron 的基础链路已经跑通，中文界面和导入导出也已初步接入。但最近一轮改动里仍有几处会影响配置正确性、用户模板数据安全和需求兑现的问题，还不建议把当前状态视为稳定可交付版本。

## P0 - 必须修复（阻塞性问题）

无。

## P1 - 建议修复（重要但不阻塞）

### [P1-1] ini 解码顺序会破坏包含反斜杠的文本内容
- **类型**：潜在 Bug / 数据损坏
- **位置**：`src/shared/import/ini-parser.ts:3`
- **描述**：`decodeIniValue()` 先把 `\\` 还原成 `\`，再把 `\n`、`\r` 转成换行。这样一来，像 `C:\new\paper` 这类原本只是普通 Windows 路径的文本，在导出再导入后会被错误解码成真实换行。
- **影响**：当前“导出当前配置 -> 再导入”不能保证文本字段稳定 round-trip。只要备注或其他文本里出现 `\n`、`\r` 形式的路径或字面量，用户数据就会被静默改写。
- **建议**：解码时不要先还原反斜杠；应先安全处理 `\n` / `\r`，或使用占位策略保证 `\\` 与转义换行不会互相污染。

### [P1-2] 模板 ID 可手输，导致界面状态与实际保存值不一致
- **类型**：逻辑错误 / 交互缺陷
- **位置**：`src/web/components/FormSections/CoreSetupSection.tsx:30`、`src/web/pages/GeneratorPage.tsx:43`、`src/web/pages/GeneratorPage.tsx:91`
- **描述**：基础设定区把 `selectedTemplateId` 暴露为自由输入框。用户输入不存在的模板 ID 后，页面右侧模板管理会因为 `selectedTemplate` fallback 到内置模板而显示“当前使用内置模板”，但 `values.selectedTemplateId` 仍然保留这个无效值，并继续被导出到 ini 或保存到最近配置里。
- **影响**：界面显示和真实配置分叉。用户看到的是一个模板，保存出去的却可能是另一个无效模板 ID，后续导入时只会收到回退警告，问题很难定位。
- **建议**：把这个字段改成只读展示，或改成基于有效模板列表的 `select`，不要允许自由手输任意 ID。

### [P1-3] 方法相关字段没有按研究方法动态收敛展示
- **类型**：功能缺失 / 需求未满足
- **位置**：`src/web/components/FormSections/VariablesSection.tsx:8`、`src/shared/validation/rule-engine.ts:3`
- **描述**：`VariablesSection` 始终展示面板 ID、时间变量、处理变量、工具变量、聚类变量等全部字段，而共享层已经有 `shouldShowPanelFields/shouldShowDidFields/shouldShowIvFields` 这些方法判断函数，但并没有接到界面上。
- **影响**：`spec` 中“根据研究类型动态展示对应字段，避免无关字段同时出现”的要求没有兑现。用户会同时看到大量当前方法不需要的字段，表单噪音大，也削弱了“按方法引导填写”的价值。
- **建议**：把 `rule-engine` 接入表单分区，至少对面板 / DID / IV 专属字段做条件渲染。

### [P1-4] 自定义模板按名称生成 ID，会无提示覆盖同名模板
- **类型**：潜在 Bug / 数据丢失
- **位置**：`src/shared/templates/template-store.ts:26`、`src/web/pages/GeneratorPage.tsx:109`
- **描述**：保存自定义模板时，模板 ID 只由名称生成；`handleSaveTemplate()` 又会直接把同 ID 的已有模板过滤掉再写入。结果是用户只要重复使用同一个名称保存模板，就会静默覆盖之前的模板，无论它们基于哪个 Stata 版本。
- **影响**：用户模板可能被无提示覆盖，尤其在“Stata 17 经典模板”和“Stata 18 现代模板”分别另存为相同中文名称时最容易发生。
- **建议**：保存前做重名检查并显式确认，或者改为真正唯一 ID，把“显示名称”与“内部 ID”解耦。

- **类型**：文档风险
- **位置**：`README_CN.md:89`、`electron-builder.yml:9`
- **描述**：文档里写“当前配置已关闭 Windows 可执行文件编辑与签名步骤，用于减少首次打包时对外网下载 `winCodeSign` 的依赖”，但是否已完全规避这类下载还没有再次实证验证。
- **建议**：等下一次完整 `npm run build:desktop` 成功后，再把这段文案收敛为事实性描述；当前更稳妥的说法应是“尝试减少依赖”。
